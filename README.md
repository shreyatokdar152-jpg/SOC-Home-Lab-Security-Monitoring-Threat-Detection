# Use Case: File Integrity Monitoring (FIM)

## Objective

Detect unauthorized creation, modification, or deletion of files in sensitive system locations (e.g., `/etc`, SSH authorized-keys files, web server document roots) using Wazuh's built-in **Syscheck** (FIM) module — no custom rule required, since FIM alerts are generated by Wazuh's default ruleset.

**MITRE ATT&CK mapping:** [T1565 – Data Manipulation](https://attack.mitre.org/techniques/T1565/) (also relevant to persistence techniques such as [T1098 – Account Manipulation](https://attack.mitre.org/techniques/T1098/) when monitoring `authorized_keys` or `/etc/passwd`)

## How it works

Wazuh's FIM module (`syscheck`) periodically scans configured directories/files, calculates checksums (and optionally full file hashes), and compares them against a baseline stored by the agent. When a change is detected, the agent reports it to the manager, which generates an alert via Wazuh's default FIM rules (rule group `syscheck`).

This use case does **not** require a custom rule — the value here is in the **configuration**: choosing the right paths to monitor, tuning scan frequency, and enabling real-time (`whodata`/`realtime`) monitoring where the OS supports it, so changes are detected within seconds rather than at the next scheduled scan.

## Configuration

Added to the agent's `ossec.conf` (or centrally via the agent's group configuration `agent.conf` on the manager) inside `<syscheck>`:

```xml
<syscheck>
  <disabled>no</disabled>

  <!-- Scan on startup, then every 12 hours -->
  <frequency>43200</frequency>

  <!-- Critical Linux config directory, real-time via inotify -->
  <directories realtime="yes" report_changes="yes">/etc</directories>

  <!-- SSH authorized_keys — classic persistence target -->
  <directories realtime="yes" report_changes="yes" restrict="authorized_keys$">/home,/root</directories>

  <!-- Web root, if applicable -->
  <directories realtime="yes" report_changes="yes">/var/www/html</directories>

  <!-- Reduce noise: ignore common log/cache churn -->
  <ignore>/etc/mtab</ignore>
  <ignore>/etc/hosts.deny</ignore>
  <ignore>/etc/random-seed</ignore>
  <ignore type="sregex">.log$|.swp$</ignore>
</syscheck>
```

`realtime="yes"` uses the kernel's `inotify` (Linux) to detect changes immediately instead of waiting for the next scheduled scan. `report_changes="yes"` has the agent store a diff of what changed, viewable directly in the dashboard.

## Testing / attack simulation

To validate the configuration, simulated a persistence attempt by appending an attacker-controlled SSH key:

```bash
# On the monitored endpoint (simulating attacker persistence)
echo "ssh-ed25519 AAAAC3Nza...simulated-test-key attacker@test" >> ~/.ssh/authorized_keys
```

And a config-tampering simulation:

```bash
sudo sed -i 's/#PermitRootLogin prohibit-password/PermitRootLogin yes/' /etc/ssh/sshd_config
```

Both changes were picked up by the agent's real-time FIM within seconds and forwarded as alerts.

## Result

Alerts appeared in **Wazuh Dashboard → File Integrity Monitoring**, showing:
- The exact file path changed
- Whether it was added, modified, or deleted
- A diff of the actual content change (`report_changes`)
- The user/process that made the change, when `whodata` auditing is enabled (Linux: via `auditd` integration; Windows: via the Security Event Log)

See [`screenshots/`](screenshots/) for the alerts as they appeared in the dashboard.

## Suggested follow-up (not implemented here)

- Enable `whodata` mode (instead of plain `realtime`) to capture **which user/process** made the change, not just that it changed — requires `auditd` on Linux or SACL configuration on Windows.
- Add FIM coverage for Windows Registry keys commonly abused for persistence (`Run`/`RunOnce` keys) via `<windows_registry>`.
- Pair critical-file alerts with Active Response to automatically quarantine or roll back unauthorized changes.
